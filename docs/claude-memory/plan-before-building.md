做功能前先和用户一起策划：把需要用户定的设计点一项项问清楚（用带选项的提问效果好，用户会直接选，也常在“其他”里写自己的想法），整理成策划让用户确认，等用户明确说“做吧/开始”再写代码。做完一小步就交给用户进游戏试，再做下一步。

**Why:** 2026-11-19 用户只说了一句“做一个有职业和经济的 NPC 模组”，我直接自己定了全部设计并开始写，被打断。用户原话：“我需要你跟我一起策划怎么做而不是我一句话你做完之后我不满意”。之后几轮提问里，用户多次推翻我的默认推荐（要全部真实工作、要集市摊位、不要手杖、不要矿工、要地图划区、要性别年龄），说明默认方案经常不是他想要的。

**How to apply:** 适用于这个项目里所有新功能和新阶段（见 [[townfolk-design-decisions]]）。涉及玩法、画风、数值这类设计取舍时先问；纯技术实现细节（API、代码结构）不用问。提问时把后果讲清楚（例如“3 天长 1 岁 = 现实 18 小时才成年”），用户会据此调整。用户说中文，回复用中文。
